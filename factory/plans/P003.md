# P003 계획 (상위 세션 초안, 사람이 확인·수정)

목표: 1차 화면은 기능만 있고 디자인이 없다 (CSS 10줄). 사람이 승인한 `DESIGN.md`(shadcn/ui neutral)를 화면 전체에 적용한다. 디자인 기반(Tailwind CSS v4, shadcn/ui 컴포넌트 10개, 토큰, `@/` 경로 별칭)은 사람 직접 항목으로 이미 `main`에 들어갔다 (`8dcec4f`). 화면 파일 단위로 작업을 나누어 서로 다른 파일은 동시에 돈다.

공통 규칙 (모든 작업):
- `DESIGN.md`를 먼저 읽고 4장 컴포넌트 대응, 5장 상태, 6장 접근성을 따른다. 색·간격·반경은 토큰 클래스만, `#hex`·인라인 style 금지. 컴포넌트는 `frontend/src/components/ui/`에 있는 것만 쓰고 새 shadcn 컴포넌트나 npm 패키지를 추가하지 않는다 (`package.json`은 잠긴 파일).
- **기존 테스트(수락 테스트 포함)는 바꾸지 않고 모두 통과해야 한다.** 역할(button, textbox, checkbox, status, alert, region)과 접근 가능한 이름(버튼 글자, aria-label, label 글자, 문구)을 그대로 둔다 (`DESIGN.md` 4장 테스트 호환 규칙).
- 동작(API 호출, 상태 전환, 문구)은 바꾸지 않는다. 바뀌는 것은 마크업 구조와 클래스뿐이다.
- 수락 테스트는 디자인 적용 여부를 확인한다: shadcn/ui 컴포넌트는 `data-slot` 속성(`button`, `card`, `input`, `textarea`, `badge`, `alert`, `skeleton`)을 남기므로 그 속성으로 찾는다. 지금 화면에는 `data-slot`이 없어 구현 전에 Red다.
- 화면 모양은 사람이 보고 판단하므로 contract 위험은 **MEDIUM으로 선언**한다 (자동 머지하지 않음).
