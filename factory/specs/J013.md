# J013 찾기 화면 (F3)

계획 P001 작업 E. `찾기` 탭에서 검색어로 `GET /api/search`(노트·결정 사항)를 부르고, 질문으로 `POST /api/ask`(근거 붙인 답변, J012)를 부르는 화면.

## 설계 (사람이 합의함)

- 새 컴포넌트 `frontend/src/Search.tsx`. prop `onOpenNote(id: number)`.
- `frontend/src/api.ts`에 `search(q) → {notes, decisions}`, `ask(question) → {answer, sources}` 추가. 오류 응답은 J009와 같은 방식(`ApiError`, `detail.message`·`detail.problems`)으로 던진다.
- `App.tsx`에 `찾기` 탭 버튼과 view `{kind: "search"}`를 추가하고, 항목 클릭은 기존 `openNote(id)`를 `onOpenNote`로 넘겨 쓴다 (노트 상세는 노트 탭에서 보이므로 열 때 노트 탭으로 바꾼다. `openOriginNote`와 같은 동작).

## 백엔드 응답 (바꾸지 않음)

- `GET /api/search?q=<검색어>` → `{notes: [{id, title, snippet, created_at}], decisions: [{id, note_id, note_title, text, created_at}]}`. 빈 검색어는 422.
- `POST /api/ask` `{question}` → `{answer, sources: [{id, title, created_at}]}`. 502는 `detail: {message, problems}`, 422는 FastAPI 검사 오류 목록 또는 문자열.

## 화면 요구사항

접근 가능한 이름(테스트가 쓰는 이름)은 아래와 같이 정한다.

1. 탭 버튼 `노트`, `할 일` 옆에 **`찾기`** 탭 버튼이 있다. 누르면 찾기 화면이 보이고 노트 목록·`새 노트`·`정리`는 보이지 않는다. `노트` 탭을 누르면 노트 목록으로 돌아간다.
2. 검색: 입력칸(textbox) **`검색어`** 와 버튼 **`검색`**. 검색어가 비었거나 공백뿐이면 `검색` 버튼은 `disabled`. 누르면 `GET /api/search?q=<검색어>`(URL 인코딩)를 부른다.
3. 검색 결과는 두 영역으로 나눈다: `aria-label`이 **`노트 결과`** 인 영역과 **`결정 사항 결과`** 인 영역 (`<section aria-label>`, role `region`).
   - 노트 결과의 각 항목은 버튼 하나이고, 안에 노트 제목과 snippet이 보인다.
   - 결정 사항 결과의 각 항목은 버튼 하나이고, 안에 결정 내용과 노트 제목(`note_title`)이 보인다.
   - 노트 항목을 누르면 그 노트(`id`), 결정 항목을 누르면 그 결정의 노트(`note_id`)로 `onOpenNote`를 불러 노트 상세(제목 heading)를 연다.
   - 한 쪽만 비었으면 그 영역 안에 `없음`을 보여 준다.
   - 노트와 결정 사항이 모두 비었으면 두 영역 없이 `없음` 하나만 보여 준다.
4. 질문: 입력칸(textbox) **`질문`** 과 버튼 **`질문`**. 질문이 비었거나 공백뿐이면 `질문` 버튼은 `disabled`. 누르면 `POST /api/ask`에 `{"question": 질문}`을 보낸다.
5. 답변은 `aria-label`이 **`답변`** 인 영역(role `region`)에 보인다. 영역 안에 답변 문장이 있고, `sources`가 있으면 각 근거 노트 제목이 버튼으로 보인다. 근거 버튼을 누르면 그 노트 상세를 연다.
   - 답이 `없음`이고 `sources`가 비었으면 영역 안에 `없음`만 보이고 근거 버튼은 없다.
6. 오류: 검색이 2xx가 아니거나 네트워크 오류면 `role="alert"` 요소에 `검색하지 못했습니다`, 질문이 실패하면 `질문하지 못했습니다`와 (있으면) `detail.message`, `detail.problems`의 각 항목을 보여 준다. 입력한 검색어·질문은 지우지 않는다.

## 제약

- 백엔드, 기존 노트·할 일 탭 동작, 기존 테스트는 바꾸지 않는다. 새 의존성 없음.
- 수락 테스트는 `fetch`를 가짜로 바꿔 화면 동작만 본다. e2e는 넣지 않는다 (계획의 가정).
