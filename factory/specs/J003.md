# J003 정리 결과 스키마와 검사

기획안 12.2 작업 3, F1(회의록·메모 정리). 회의록 정리 스킬이 낼 결과 JSON의 형식을 백엔드 모듈로 정의하고 검사한다.

## 요구사항

- 새 모듈 `backend/src/randomy/notes_result.py`에 결과 형식과 `validate_result(data)`를 둔다.
- 형식 (JSON 객체):
  - `summary`: 빈 문자열이 아닌 문자열.
  - `decisions`: 문자열 목록. 비어 있어도 된다.
  - `todos`: 객체 목록. 비어 있어도 된다. 각 객체는
    - `task`: 빈 문자열이 아닌 문자열
    - `owner`: 문자열 또는 `null`
    - `due`: 문자열 또는 `null`
  - 위 필드는 모두 있어야 한다. 정해진 필드 외의 필드(최상위, todo 객체 안 모두)가 있으면 형식 오류다.
- `validate_result(data)`는 문제 목록(한국어 문자열의 `list[str]`)을 돌려준다. 문제가 없으면 `[]`.
  - 각 문제 문구에는 문제가 있는 필드 경로가 들어간다 (예: `summary`, `decisions[1]`, `todos[1].task`). 정해진 필드 외의 필드는 그 필드 이름이 들어간다.
  - 문제가 여러 개면 모두 보고한다.
  - `data`가 객체(dict)가 아니면 문제 하나 이상을 돌려준다 (예외를 내지 않는다).

## 제약

- 백엔드 모듈과 테스트만 다룬다. `skills/meeting-notes/schema.json`은 만들지 않는다.
- API 경로·DB·`settings.py`·`model.py`는 바꾸지 않는다.
- 새 의존성을 추가하지 않는다. 모델을 호출하지 않는다.
