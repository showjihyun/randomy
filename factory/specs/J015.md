# J015 찾기·주간 정리 화면의 요청 중 상태 처리 (P001 리뷰 지적 후속)

J013(찾기)·J014(주간 정리) 화면에 요청 중 표시, 중복 요청 막기, 늦게 온 응답 버리기, 오류 분리·재시도를 더한다. 화면 문구와 기존 동작(J013·J014 수락 테스트)은 그대로 둔다.

## 찾기 화면 (`frontend/src/Search.tsx`)

1. 검색 요청 중에는 `검색` 버튼을 막고(disabled, 버튼 이름은 `검색` 그대로) 텍스트 **`검색 중…`**을 보여 준다. 응답이 오면(성공·실패 모두) 문구를 지우고 버튼을 다시 연다.
2. 질문 요청 중에는 `질문` 버튼을 막고(이름은 `질문` 그대로) 텍스트 **`답변을 만드는 중…`**을 보여 준다. 응답이 오면 문구를 지우고 버튼을 다시 연다.
3. 검색과 질문은 서로 독립이다: 검색 중에도 `질문` 버튼은 (질문이 비어 있지 않으면) 눌 수 있고, 반대도 같다.
4. 새 검색을 시작하면 이전 검색 결과(`노트 결과`·`결정 사항 결과`·`없음`)와 이전 검색 오류를 바로 지운다. 새 질문을 시작하면 이전 답변(`답변` 구역)과 이전 질문 오류를 바로 지운다. 다른 쪽 결과·오류는 건드리지 않는다.
5. 검색 오류(`검색하지 못했습니다` …)와 질문 오류(`질문하지 못했습니다` …)는 각자 `role="alert"` 요소로 따로 보여 주며, 동시에 둘 다 보일 수 있다.
6. 검색 폼이 요청 중에 다시 제출되면(예: 프로그램적 submit) 새 요청을 시작하고, 먼저 보낸 요청의 응답은 늦게 와도 버린다. 질문도 같다. 마지막 요청의 응답(성공·실패)만 화면에 반영된다.

## 주간 정리 화면 (`frontend/src/Weekly.tsx`)

1. 불러오는 중에는 텍스트 **`불러오는 중…`**을 보여 준다. `지난주`·`다음 주`로 다른 주를 부르는 동안에는 두 버튼을 그대로 보이되 막는다(disabled). 응답이 오면 문구를 지우고 버튼을 다시 연다. (처음 불러오기 중에는 버튼이 없어도 된다.)
2. 불러오기에 실패하면 `role="alert"` 요소에 `주간 정리를 불러오지 못했습니다`와 함께 버튼 **`다시 시도`**를 보여 준다. 누르면 실패한 그 주(같은 date 인자, 처음 불러오기였으면 date 없이)를 다시 부른다.
3. 실패해도 마지막으로 성공한 주가 있으면 `지난주`·`다음 주` 버튼을 남기고(눌 수 있음), 그 주의 `start` ± 7일로 부른다.

## 제약

- 백엔드, 다른 화면(정리·노트·할 일), `App.tsx`의 탭 동작, `playwright.config.ts`, 기존 테스트는 바꾸지 않는다. 새 npm 패키지 없음.
- 수락 테스트는 `fetch`를 가짜로 바꾸고, 응답을 테스트가 직접 풀어 주는 지연 응답으로 요청 중 상태를 본다.
