# J002 노트 목록·상세 화면

기획안 12.2 작업 2. J001의 노트 API(`GET /api/notes`, `GET /api/notes/{id}`)를 쓰는 화면. 노트 작성 화면은 범위 밖이다.

## 요구사항

- 첫 화면(`App`)에 `GET /api/notes`로 받은 노트 목록을 보여 준다.
  - 목록은 `<ul>`/`<li>`(role `list`/`listitem`)이고, 항목마다 제목과 작성 시각(`created_at`)을 보여 준다.
  - 순서는 최신순이다. 서버가 최신순으로 돌려주므로 받은 순서를 그대로 쓴다.
  - 작성 시각은 `created_at` 문자열을 그대로 `<time dateTime={created_at}>` 안에 보여 준다 (시간대에 따라 테스트가 달라지지 않게).
  - 각 항목은 누를 수 있는 버튼(role `button`)이고, 버튼의 이름에 제목이 들어간다.
- 노트가 없으면 '저장된 노트가 없습니다'를 보여 준다.
- 목록에서 노트를 누르면 `GET /api/notes/{id}`로 받아 상세를 보여 준다.
  - 제목은 제목 요소(role `heading`), 본문, 작성 시각(`<time>`, `created_at` 그대로)을 보여 준다.
  - 상세에서는 목록을 보여 주지 않는다.
  - '목록으로' 버튼을 누르면 목록으로 돌아간다.
- 상세를 불러오지 못하면(404 등, 응답이 ok가 아니거나 요청 실패) '노트를 찾을 수 없습니다'를 보여 주고, '목록으로' 버튼으로 돌아갈 수 있다.
- 기존 서버 연결 표시(`role="status"`, '서버 연결됨 (모델: …)' / '서버에 연결할 수 없습니다')와 `Randomy` 제목은 그대로 둔다.

## 제약

- 새 npm 패키지(라우터 등)를 추가하지 않는다. 화면 전환은 React 상태로 한다.
- 백엔드는 바꾸지 않는다.
- API 호출은 `frontend/src/api.ts`에 둔다.

## 기존 테스트 변경

`frontend/src/App.test.tsx`의 fetch 가짜는 모든 URL에 health 응답을 돌려준다. 앱이 `/api/notes`도 부르게 되면 목록 자리에 health 객체가 들어가므로, URL에 따라 health / 빈 노트 목록을 돌려주도록 바꿨다. 검사 내용(제목, 서버 연결 표시, 연결 실패 문구)은 그대로다.
