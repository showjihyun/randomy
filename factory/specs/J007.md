# J007 회의록 정리 스킬 첫 판과 정리 API

기획안 12.2 작업 4, F1(회의록·메모 정리). 제품 스킬 `meeting-notes`의 첫 지시문과, 그 지시문으로 모델을 한 번 불러 정리 결과를 돌려주는 API를 만든다. 저장(확인·수정 후 저장)과 화면은 다음 작업이다.

## 요구사항

### (1) 스킬 지시문 `skills/meeting-notes/SKILL.md`

- 한국어 지시문. 회의록·메모를 받아 결과를 **JSON 객체 하나로만** 내라고 지시한다.
- 형식은 `randomy.notes_result`와 같다: `summary`(문자열), `decisions`(문자열 목록), `todos`(객체 목록, 각 `task`·`owner`·`due`).
- 다음을 적는다.
  - 원문에 없는 결정·할 일·사람·숫자를 만들지 않는다.
  - 논의만 하고 정하지 않은 안건(보류·기각)은 `decisions`에 넣지 않는다.
  - 담당(`owner`)·기한(`due`)이 원문에 없으면 `null`.
  - 코드 블록(```) 없이 JSON만 낸다.

### (2) 모델 출력 읽기

- `randomy.notes_result`에 `parse_result(text: str) -> dict[str, Any]`와 예외 `ResultError`를 둔다.
  - 앞뒤 공백을 벗기고, 출력 전체를 감싼 코드 블록 표시(```` ```json ```` 또는 ```` ``` ````로 시작하고 ```` ``` ````로 끝남)를 벗겨 낸 뒤 JSON으로 읽는다.
  - 읽은 값을 `validate_result`로 검사한다. 문제가 없으면 그 객체를 돌려준다.
  - JSON으로 읽을 수 없거나 검사 문제가 있으면 `ResultError`를 낸다. `ResultError.problems`는 빈 목록이 아닌 문제 문자열 목록이다 (검사 문제가 있으면 `validate_result`의 문제 목록 그대로).
- `randomy.skill_cli.parse_output`도 같은 방식으로 앞뒤 공백과 코드 블록 표시를 벗겨 낸 뒤 JSON으로 읽는다. 읽을 수 없으면 지금처럼 원문 문자열을 그대로 돌려준다 (형식 검사는 하지 않는다).

### (3) `POST /api/organize`

- 본문 `{"text": <빈 문자열이 아닌 문자열>}`. `text`가 비었거나 없으면 422이고 모델을 부르지 않는다.
- `skills/meeting-notes/SKILL.md` 내용을 system 지시문으로, `text`를 prompt로 모델을 **한 번** 부른다.
- 출력을 `parse_result`로 읽어 통과하면 200과 결과 객체(`summary`, `decisions`, `todos`)를 돌려준다.
- 출력이 형식에 맞지 않으면 502, 본문 `{"detail": {"message": <문자열>, "problems": [<문자열>...]}}` (`problems`는 빈 목록이 아님).
- 모델 호출이 `ModelError`로 실패하면 502.
- 아무것도 저장하지 않는다 (노트·할 일 목록이 그대로).
- 모델은 `get_model(settings)`로 얻는다. `create_app(settings, model=None)`: `model`을 주면 그 모델을 쓴다 (테스트용 가짜 모델).

## 제약

- `settings.py`, `model.py`, `evals/`는 바꾸지 않는다.
- 테스트는 가짜 모델만 쓰고 실제 모델을 부르지 않는다.
- 새 의존성을 추가하지 않는다. 화면(frontend)은 바꾸지 않는다.
