# J006 노트 작성 화면

기획안 12.2 작업 5의 일부, F1(노트 저장 부분). 기존 노트 저장 API(`POST /api/notes`, 본문 `{"title": str, "body": str}`, 본문은 1글자 이상, 성공 시 201과 저장된 노트 `{id, title, body, created_at}`)를 쓰는 화면. 회의록 정리(모델 호출)는 범위 밖이다.

## 요구사항

- '노트' 탭의 노트 목록 화면에서 목록 위(목록 `<ul>` 밖)에 '새 노트' 버튼(role `button`, 이름 정확히 '새 노트')을 둔다. 노트가 하나도 없을 때('저장된 노트가 없습니다')도 보인다.
- '새 노트'를 누르면 작성 화면을 보여 준다.
  - 제목 입력란: 한 줄 입력(`<input>`), 접근 가능한 이름 '제목' (role `textbox`).
  - 본문 입력란: 여러 줄 입력(`<textarea>`), 접근 가능한 이름 '본문' (role `textbox`).
  - '저장' 버튼과 '취소' 버튼 (role `button`, 이름 정확히 '저장' / '취소').
- '저장'을 누르면 `POST /api/notes`에 JSON 본문 `{"title": <제목>, "body": <본문>}`을 보낸다 (Content-Type `application/json`).
  - 성공하면 응답으로 받은 노트의 상세 화면을 연다 (기존 상세 화면 재사용: 제목 heading, 본문, '목록으로'). 상세는 응답 노트로 바로 보여 주거나 `GET /api/notes/{id}`로 다시 불러와도 된다.
  - 상세에서 '목록으로'를 누르면 노트 목록이 보이고, 방금 저장한 노트가 목록에 들어 있다 (목록을 다시 불러오거나 저장한 노트를 목록에 더한다).
- 본문이 비어 있으면 요청을 보내지 않는다. 저장 버튼을 비활성화(`disabled`)하거나, 눌렀을 때 '본문을 입력하세요'를 보여 준다 (둘 중 하나).
- 서버가 오류(2xx가 아닌 응답)를 돌려주거나 요청이 실패하면 '저장하지 못했습니다'를 보여 주고, 작성 화면에 남아 입력한 제목·본문을 지우지 않는다.
- '취소'를 누르면 작성 화면을 닫고 노트 목록으로 돌아간다. 요청은 보내지 않는다.
- '할 일' 탭에는 '새 노트' 버튼이 보이지 않는다.
- 기존 노트 목록·상세, 할 일 탭, 서버 연결 표시(`role="status"`)는 그대로 동작한다. 기존 테스트(`App.test.tsx`, `App.J002.accept.test.tsx`, `App.J005.accept.test.tsx`, `e2e/`)는 바꾸지 않고 통과해야 한다.

## 제약

- 새 npm 패키지를 추가하지 않는다. 화면 전환은 React 상태로 한다.
- 백엔드는 바꾸지 않는다.
- API 호출은 `frontend/src/api.ts`에 둔다.
