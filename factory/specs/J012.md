# J012 근거 붙인 답변 스킬과 API

계획 P001 작업 D. 질문을 받아 C의 `search()`로 후보 노트를 고르고, 스킬 `answer-with-sources`를 지시문으로 모델을 한 번 불러 근거 노트가 붙은 답을 돌려주는 `POST /api/ask`를 만든다. 테스트는 가짜 모델만 쓴다.

## 설계 (사람이 합의함)

- `skills/answer-with-sources/SKILL.md` (지시문만, 스크립트 없음). 한국어 지시문:
  - 입력은 질문과 후보 노트(id, 제목, 요약, 결정 사항, 원문).
  - 결과는 JSON 객체 하나 `{"answer": 문자열, "sources": [노트 id 정수]}`로만 낸다.
  - 후보 노트에 근거가 있는 내용만 답한다. 근거가 없으면 `answer`를 `"없음"`, `sources`를 빈 배열로 낸다.
  - 후보에 없는 id·결정·사람·숫자를 만들지 않는다. 코드 블록(```) 없이 JSON만 낸다.
- 새 모듈 `backend/src/randomy/ask.py`:
  - `validate_answer(data) -> list[str]`: 문제 목록 (없으면 `[]`). `data`는 객체, `answer`는 문자열, `sources`는 정수 목록(bool은 정수로 보지 않음), 그 밖의 필드는 문제.
  - `parse_answer(text) -> dict`: `notes_result.strip_fence`로 코드 블록을 벗기고 JSON으로 읽어 검사한다. 실패하면 `notes_result.ResultError(problems)`.
  - `build_prompt(question, candidates) -> str`: 질문과, 후보마다 `[노트 <id>] 제목 / 요약 / 결정 / 원문` 블록을 이어 붙인다. 원문은 노트당 앞부분 일정 길이로 자른다.
  - `create_ask_router(db_path, model_provider)`를 `main.create_app`에서 `include_router`한다. 모델은 organize와 같이 `create_app`의 `model` 인자가 있으면 그것을, 없으면 `get_model(settings)`.
- 후보 고르기: 질문 문자열을 그대로 `search(db_path, question)`에 넣는다. 노트·결정 결과가 모두 없으면 질문을 공백으로 나눈 단어마다 `search()`를 불러 합친다 (OR 완화). 후보 노트는 노트 결과의 id와 결정 결과의 `note_id`를 순서대로 중복 없이 모아 최대 5개. 각 후보의 제목·원문·created_at·요약(summaries)·결정(decisions)을 읽어 프롬프트를 만든다.

## 요구사항

### `POST /api/ask` 본문 `{"question": 문자열}`

- `question`이 없거나, 문자열이 아니거나, 비었거나, 공백뿐이면 422 (모델을 부르지 않음).
- 후보가 없으면 (저장된 노트가 없거나 일치가 없음) 모델을 부르지 않고 200 `{"answer": "없음", "sources": []}`.
- 후보가 있으면 모델을 **한 번** 부른다. `system`은 SKILL.md 내용 그대로, `prompt`는 `build_prompt(question, candidates)` (질문 원문과 후보마다 `[노트 <id>]`, 제목, 요약, 결정, 잘린 원문 포함). 후보가 아닌 노트는 프롬프트에 넣지 않는다.
- 모델 출력이 `parse_answer`를 통과하고 `sources`가 모두 후보 id이면 200 `{"answer": ..., "sources": [{"id", "title", "created_at"}...]}` (모델이 낸 순서).
- `sources`에 후보에 없는 id가 있으면 502 `{"detail": {"message", "problems"}}` (problems에 그 id가 나온다).
- 출력 형식이 틀리면 (JSON 아님, 필드 누락·타입 오류·정해지지 않은 필드) 502 `{"detail": {"message", "problems"}}`.
- `ModelError`면 502 `{"detail": {"message", "problems"}}`.

## 제약

- `settings.py`, `model.py`, `evals/`, `scripts/`, 화면(frontend)은 바꾸지 않는다. 기존 API 동작과 표 구조는 그대로. 새 의존성 없음.
- 테스트는 가짜 모델만 쓴다. 실제 모델 호출 경로는 기존 `get_model` 그대로다.
