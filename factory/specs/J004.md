# J004 할 일 저장·목록·완료 API

기획안 12.2 작업 6a, F2(할 일). 노트에 딸린 할 일을 노트와 같은 SQLite(`Settings.db_path`)에 저장한다. 화면은 범위 밖이다.

## 요구사항

- 할 일 입력 필드는 정리 결과 스키마(`randomy.notes_result`의 `todos`)와 같다.
  - `task`: 빈 문자열이 아닌 문자열 (필수)
  - `owner`: 문자열 또는 null (생략하면 null)
  - `due`: 문자열 또는 null (생략하면 null)
- 저장된 할 일 응답은 정확히 `{"id", "note_id", "task", "owner", "due", "done", "created_at"}` 필드를 가진다. `done`은 처음에 `false`, `created_at`은 ISO 8601 문자열이다.
- `POST /api/notes/{note_id}/todos`: 할 일 하나를 추가하고 201과 할 일을 돌려준다.
  - 노트가 없으면 404 (할 일이 저장되지 않는다).
  - `task`가 빈 문자열이거나 없으면 422 (할 일이 저장되지 않는다).
- `GET /api/todos`: 할 일 전체. 완료 안 된 것(`done=false`)을 먼저, 같은 그룹 안에서는 최신순(나중에 저장한 것이 먼저, 같은 시각이어도 나중에 저장한 것이 먼저).
  - 쿼리 `done=true` / `done=false`로 그 그룹만 돌려준다. 순서는 같은 규칙(최신순).
- `PATCH /api/todos/{id}` 본문 `{"done": bool}`: 완료 표시를 바꾸고 바뀐 할 일 전체를 돌려준다(200). 없으면 404. `done`이 없으면 422.
- 같은 `db_path`로 앱을 다시 만들어도 할 일과 완료 표시가 남아 있다.
- 기존 노트 API(`/api/notes`, `/api/notes/{id}`)의 동작·응답 형식은 바뀌지 않는다.

## 제약

- `settings.py`, `model.py`는 바꾸지 않는다.
- 새 의존성을 추가하지 않는다.
- 모델을 호출하지 않는다.
- 화면(frontend)은 바꾸지 않는다.
