# J009 정리 화면 (F1)

계획 P001 작업 B. 노트 탭에서 회의록·메모를 붙여넣고 `POST /api/organize`로 정리한 뒤, 사람이 결과를 확인·수정해서 `POST /api/organized`(J008)로 한 번에 저장하는 화면.

## 설계 (사람이 합의함)

- 새 컴포넌트 `frontend/src/Organize.tsx`. 상태: 원문, 정리 중 여부, 편집 중인 결과 `{title, summary, decisions: string[], todos: {task, owner, due}[]}`, 오류.
- `frontend/src/api.ts`에 `organize(text) → OrganizeResult`, `saveOrganized(payload) → {note, summary, decisions, todos}` 추가. 오류 응답은 `detail.message`·`detail.problems`를 담은 `Error`로 던진다.
- `App.tsx`의 view에 `{kind: "organize"}`를 추가하고, 저장 성공 시 기존 `openNote(id)` 흐름으로 노트 상세를 연다.

## 화면 요구사항

접근 가능한 이름(테스트가 쓰는 이름)은 아래와 같이 정한다.

1. 노트 탭 목록 화면(`새 노트` 버튼이 보이는 곳)에 버튼 **`정리`** 가 보인다. 할 일 탭에는 없다. 누르면 정리 화면으로 바뀌고 목록·`새 노트`·진입점 `정리` 버튼은 사라진다.
2. 정리 화면에는 원문 입력칸(textarea, 이름 **`원문`**)과 버튼 **`정리`** 가 있다.
   - 원문이 비었거나 공백뿐이면 `정리` 버튼은 `disabled`.
   - 누르면 `POST /api/organize`에 `{"text": 원문}`을 보낸다. 응답을 기다리는 동안 `정리` 버튼은 `disabled`.
3. 성공(200, `{summary, decisions: string[], todos: [{task, owner, due}]}`)하면 편집칸을 보여 준다.
   - 제목 input **`제목`** (처음엔 빈 값), 요약 textarea **`요약`** (받은 요약).
   - 결정 사항 i번째(1부터): input **`결정 i`**, 지우기 버튼 **`결정 i 삭제`**. 추가 버튼 **`결정 추가`** (빈 입력칸 하나를 끝에 추가).
   - 할 일 i번째: input **`할 일 i`**(task), **`담당 i`**(owner, null이면 빈 값), **`기한 i`**(due, null이면 빈 값), 지우기 버튼 **`할 일 i 삭제`**. 추가 버튼 **`할 일 추가`** (빈 행 하나를 끝에 추가).
   - 제목·결정·할 일·담당·기한은 모두 텍스트 입력칸(접근성 role `textbox`, 기한도 `type="date"`가 아닌 텍스트)이다.
   - 결정 사항이 하나도 없으면 결정 영역에 `없음`, 할 일이 하나도 없으면 할 일 영역에 `없음`을 보여 준다 (받은 결과가 비었을 때, 사람이 다 지웠을 때 모두).
   - 원문 입력칸은 그대로 남아 있다.
4. 버튼 **`저장`** 을 누르면 `POST /api/organized`를 한 번 부른다. 본문은 `{title, body: 원문, summary, decisions, todos: [{task, owner, due}]}`이고, 화면 순서대로 넣는다. 담당·기한 입력칸이 빈 문자열이면 `null`로 보낸다. 그 밖의 값은 입력한 그대로 보낸다.
   - 성공(201)하면 응답의 `note`를 노트 목록 맨 앞에 넣고 `openNote(note.id)`로 그 노트 상세(제목 heading)를 연다. `목록으로`를 누르면 목록에 새 노트가 보인다.
   - 실패하면 `role="alert"` 요소에 `저장하지 못했습니다`와 (있으면) `detail.message`, `detail.problems`의 각 항목을 보여 주고, 편집 중인 값과 원문은 그대로 둔다.
5. 정리 실패(422, 502 등 2xx가 아닌 응답, 또는 네트워크 오류)면 `role="alert"` 요소에 `정리하지 못했습니다`와 (있으면) `detail.message`, `detail.problems`의 각 항목을 보여 준다. 원문 입력칸 내용은 지우지 않는다. 422의 `detail`은 FastAPI 검사 오류 목록이므로 `message`가 없을 수 있다.
6. 정리 화면에서 `노트` 탭 버튼을 누르면 목록으로 돌아간다 (기존 `showNotesTab` 동작).

- 기존 노트·할 일 화면 동작, 백엔드, `frontend/playwright.config.ts`는 바꾸지 않는다. 새 의존성 없음.
