# J011 주간 정리 API

계획 P001 작업 F. 한 주(월요일~일요일)에 저장한 노트·요약·결정 사항과, 아직 끝내지 않은 할 일 전체를 모아 돌려주는 결정적 집계 API. 모델은 부르지 않고 저장된 데이터만 읽는다. 화면(작업 G)이 이 API를 부른다.

## 설계 (사람이 합의함)

- 새 모듈 `backend/src/randomy/weekly.py`:
  - `week_range(day: date) -> tuple[date, date]` 순수 함수: 그 날짜가 속한 주의 월요일과 일요일.
  - `weekly(db_path, day)` 집계 함수.
  - `create_weekly_router(db_path)`를 `main.create_app`에서 `include_router`한다.
- 기간 비교는 `created_at` 문자열의 날짜 부분(앞 10글자, `YYYY-MM-DD`)으로 `start <= 날짜 <= end`.
- 쿼리:
  - notes `LEFT JOIN summaries` (요약 없는 노트는 `summary: null`)
  - decisions `JOIN notes` (`note_title`)
  - todos `WHERE done = 0 ORDER BY due IS NULL, due, created_at` (같으면 `id`)
- 읽기만 한다. 새 표·`CREATE`/`ALTER TABLE` 없음. 기존 notes·todos·summaries·decisions 표 구조는 그대로.

## 요구사항

### `GET /api/weekly?date=YYYY-MM-DD`

- `date`를 생략하면 오늘(`date.today()`, 서버 로컬 날짜).
- 200, `{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD", "notes": [...], "decisions": [...], "open_todos": [...]}`
  - `start`는 그 주 월요일, `end`는 일요일.
  - `notes`: 그 주에 만든 노트 `{"id", "title", "summary", "created_at"}`. `summary`는 summaries 표의 값, 없으면 `null`. 만든 순서(`created_at` 오름차순, 같으면 `id` 오름차순).
  - `decisions`: 그 주에 만든 결정 사항 `{"id", "note_id", "note_title", "text", "created_at"}`. `note_title`은 그 결정이 속한 노트의 제목. 만든 순서(`created_at` 오름차순, 같으면 `id` 오름차순).
  - `open_todos`: 만든 시점과 관계없이 `done`이 아닌 할 일 전체, `GET /api/todos`와 같은 `TodoOut` 형식. 기한이 있는 것 먼저 기한 오름차순, 그다음 기한 없는 것. 같으면 `created_at`, `id` 오름차순.
  - 저장된 것이 없으면 세 배열 모두 `[]`.
- `date`가 `YYYY-MM-DD` 형식의 실제 날짜가 아니면(`2026-13-01`, `2026-02-30`, `20261021`, `2026/10/21`, 빈 문자열 등) 422.

## 제약

- 모델을 부르지 않는다. 저장된 데이터를 바꾸지 않는다.
- 기존 표 구조와 기존 API 동작은 바꾸지 않는다.
- `settings.py`, `model.py`, `evals/`, `skills/`, 화면(frontend)은 바꾸지 않는다. 새 의존성 없음.
