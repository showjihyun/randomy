# J019 주간 정리 시간대 처리

P002 J018 리뷰 후속. 지금 `GET /api/weekly`는 오늘을 서버 로컬 날짜(`date.today()`)로 정하면서, 노트·결정이 어느 주에 속하는지는 UTC로 저장된 `created_at` 문자열의 앞 10자로 판단한다. 그래서 KST 월요일 00~09시에 만든 노트가 지난주로 잡힌다.

## 고칠 내용

- `backend/src/randomy/weekly.py`의 `weekly`에 선택 인자 `tz`를 추가한다 (기본값: 서버 로컬 시간대).
- 노트·결정의 주 소속은 SQL의 `substr` 비교 대신 파이썬에서 `datetime.fromisoformat(created_at).astimezone(tz).date()`가 `start <= 날짜 <= end`인지로 판단한다.
- 오늘도 같은 시간대의 날짜로 정한다. `weekly`의 `day`를 생략(`None`)하면 `tz` 기준 오늘이 속한 주다.
- 라우터(`GET /api/weekly`)는 `tz` 기본값(서버 로컬)을 쓴다.

## 바꾸지 않는 것

- 저장 형식(`created_at` UTC ISO), API 응답 모양, 정렬 순서, 남은 할 일 규칙(`done = 0` 전체).
- `settings.py`, `model.py`, 화면(frontend), 표 구조. 새 의존성 없음.

## 기존 테스트 변경

- `backend/tests/acceptance/test_J011.py`: 주 경계 상수(월요일 00:00, 일요일 23:59:59 UTC 등)가 서버 로컬 시간대(예: KST)로 바꾸면 다른 주로 넘어간다. 시간대와 관계없이 같은 날짜가 되도록 `MONDAY`, `SUNDAY`, `LAST_SUNDAY`, `NEXT_MONDAY`를 UTC 정오로 바꿨다. 자정 경계는 `test_J019.py`가 `tz`를 지정해 확인한다.
