# J014 주간 정리 화면 (F4)

계획 P001 작업 G. `주간 정리` 탭에서 `GET /api/weekly`(J010~J011에서 만든 읽기 전용 API)를 불러 한 주의 노트·결정 사항·남은 할 일을 구역별로 보여 주는 화면.

## 설계

- 새 컴포넌트 `frontend/src/Weekly.tsx`. prop `onOpenNote(id: number)`.
- `frontend/src/api.ts`에 `fetchWeekly(date?: string) → {start, end, notes, decisions, open_todos}` 추가. `date`가 없으면 `GET /api/weekly`, 있으면 `GET /api/weekly?date=YYYY-MM-DD`. 2xx가 아니면 던진다.
- `App.tsx`에 `주간 정리` 탭 버튼을 추가하고, 항목 클릭은 기존 `openOriginNote(id)`(노트 탭으로 바꾸고 `openNote(id)`)를 `onOpenNote`로 넘긴다.

## 백엔드 응답 (바꾸지 않음)

- `GET /api/weekly[?date=YYYY-MM-DD]` → `{start, end, notes: [{id, title, summary: string|null, created_at}], decisions: [{id, note_id, note_title, text, created_at}], open_todos: [{id, note_id, task, owner, due, done, created_at}]}`. `start`는 그 주 월요일, `end`는 일요일 (`YYYY-MM-DD`). date가 없으면 서버의 오늘. 잘못된 date는 422.

## 화면 요구사항

접근 가능한 이름(테스트가 쓰는 이름)은 아래와 같이 정한다.

1. 탭 버튼 `노트`, `할 일`, `찾기` 옆에 **`주간 정리`** 탭 버튼이 있다. 누르면 date 없이 `GET /api/weekly`를 부르고 주간 정리 화면을 보인다. 노트 목록·`새 노트`·`정리`는 보이지 않는다. `노트` 탭을 누르면 노트 목록으로 돌아간다.
2. 기간은 **`<start> ~ <end>`** 텍스트 하나로 보인다 (예: `2026-10-19 ~ 2026-10-25`).
3. 세 구역은 `aria-label`이 **`이번 주 노트`**, **`결정 사항`**, **`남은 할 일`** 인 `<section>`(role `region`)이다.
   - 이번 주 노트: 항목마다 버튼 하나, 안에 제목과 요약(`summary`가 null이면 제목만).
   - 결정 사항: 항목마다 버튼 하나, 안에 결정 내용(`text`)과 노트 제목(`note_title`).
   - 남은 할 일: 항목마다 목록 항목(listitem) 하나, 안에 `task`, owner가 있으면 `담당: <owner>`, due가 있으면 `기한: <due>`. 버튼은 없다.
   - 구역이 비면 그 구역 안에 `없음`을 보여 준다 (구역은 항상 셋 다 보인다).
4. 노트 항목을 누르면 그 노트(`id`), 결정 항목을 누르면 그 결정의 노트(`note_id`) 상세(제목 heading)를 연다.
5. 버튼 **`지난주`**, **`다음 주`**: 지금 보이는 `start`에서 7일 빼거나 더한 날짜로 `GET /api/weekly?date=<YYYY-MM-DD>`를 다시 부르고 새 응답으로 화면을 바꾼다. 날짜 계산은 달·해가 바뀌어도 맞아야 한다 (시간대에 따라 하루 밀리지 않게 `YYYY-MM-DD` 문자열 기준으로 계산).
6. 불러오기가 2xx가 아니거나 네트워크 오류면 `role="alert"` 요소에 `주간 정리를 불러오지 못했습니다`를 보여 준다.

## 제약

- 백엔드, 기존 노트·할 일·찾기 탭 동작, 기존 테스트는 바꾸지 않는다. 새 의존성 없음.
- 수락 테스트는 `fetch`를 가짜로 바꿔 화면 동작만 본다. e2e는 넣지 않는다 (계획의 가정).
