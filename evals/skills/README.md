# 스킬 평가 케이스

`make eval-skills` (`python scripts/eval_skills.py [<스킬>...]`)가 읽는다.

- 위치: `evals/skills/<스킬>/cases/<케이스>.json`
- 형식:

```json
{
  "id": "deploy-meeting",
  "input": "회의록 원문",
  "expect": {
    "fields": ["summary", "decisions", "todos"],
    "contains": ["배포는 금요일"],
    "absent": ["원문에 없는 할 일"],
    "absent_in": {"decisions": ["보류된 안건"]}
  }
}
```

- `contains`: 출력에 꼭 들어갈 결정·할 일. `absent`: 원문에 없어 나오면 안 되는 내용 (나오면 지어내기).
- `absent_in`: 그 필드에만 나오면 안 되는 내용. 보류·기각된 안건처럼 요약에서 언급하는 것은 맞지만 `decisions`에 들어가면 지어내기인 경우에 쓴다.
- 판정 (기획안 12.2, 임시값): 케이스마다 3회 실행, 케이스 통과 = 3회 중 2회 이상, 스킬 통과 = 케이스 90% 이상 + 지어내기 0건. 평가 1회 비용 상한 $1.
- **케이스는 사람이 만들고 승인한다.** 수락 테스트와 같은 지위라 잠금·HIGH다. 팩토리 작업은 읽을 수 있지만 바꾸거나 새로 만들 수 없다.
- **이 레포는 공개다.** 실제 회의록을 넣을 때는 사람 이름, 회사·고객 이름, 금액, 내부 일정 같은 민감한 내용을 빼거나 바꾼 뒤 넣는다.
